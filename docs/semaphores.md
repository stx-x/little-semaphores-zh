# 信号量

<div class="chap-en">Semaphores</div>

<div class="chap-en">Semaphores</div>

在现实生活中，信号量（semaphore）是一套用于视觉通信的信号系统，通常借助旗子、灯光或某种其他装置。在软件中，信号量是一种数据结构，可用于解决各种同步问题。

信号量由埃兹格·迪杰斯特拉（Edsger Dijkstra）发明，他是一位以性情古怪著称的计算机科学家。自最初的设计以来，一些细节已有变化，但基本思想始终相同。

## 定义

信号量就像一个整数，只是有三点不同：

1.  创建信号量时，你可以把它的值初始化为任意整数，但此后你唯一被允许执行的操作就是自增（加一）和自减（减一）。你无法读取信号量的当前值。

2.  当线程对信号量做自减时，如果结果为负，该线程就阻塞自己，直到另一个线程对信号量做自增，它才能继续。

3.  当线程对信号量做自增时，如果有其他线程在等待，那么其中一个等待的线程会被解除阻塞。

说一个线程阻塞自己（或简称“阻塞”），意思是它通知调度器自己无法继续。调度器会阻止该线程运行，直到发生某个事件使该线程解除阻塞。按照计算机科学中混用隐喻的传统，解除阻塞常常被称为“唤醒”（waking）。

定义就这么多，不过这个定义还有一些推论，你也许愿意想一想。

-   一般而言，在线程对信号量做自减之前，无法知道它会不会阻塞（在某些具体情形下，你或许能证明它会或不会）。

-   一个线程对信号量做自增、另一个线程被唤醒之后，两个线程会并发地继续运行。无法知道哪一个线程（如果有的话）会立刻继续。

-   当你对一个信号量发信号时，你并不一定知道是否有别的线程在等待，所以被解除阻塞的线程数可能是零，也可能是一个。

最后，你也许愿意想一想信号量的值意味着什么。如果值为正，那么它表示还有多少个线程可以做自减而不被阻塞。如果值为负，那么它表示已经阻塞、正在等待的线程数。如果值为零，意味着没有线程在等待，但若有线程试图做自减，它就会阻塞。

## 语法

在大多数编程环境中，信号量的实现作为编程语言或操作系统的一部分提供。不同的实现有时提供略有差异的能力，通常也要求不同的语法。

本书中我将用一种简单的伪语言来演示信号量的工作原理。创建新信号量并初始化它的语法是

```python title="Semaphore initialization syntax"
fred = Semaphore(1)
```

`Semaphore` 是一个构造函数；它创建并返回一个新的信号量。信号量的初始值作为参数传给该构造函数。

信号量的操作在不同环境中有不同的名字。最常见的几种替代写法是

```python title="Semaphore operations"
fred.increment()
fred.decrement()    
```

以及

```python title="Semaphore operations"
fred.signal()
fred.wait() 
```

以及

```python title="Semaphore operations"
fred.V()
fred.P()    
```

名字如此之多也许令人意外，但这自有原因。`increment` 和 `decrement` 描述的是这些操作*做什么*。`signal` 和 `wait` 描述的是它们通常*用于什么*。而 `V` 和 `P` 是迪杰斯特拉最初提出的名字，他明智地意识到，一个无意义的名字胜过一个有误导性的名字[^1]。

我认为另外几对名字都有误导性，因为 `increment` 和 `decrement` 没有提及阻塞与唤醒的可能性，而信号量的用法常常与 `signal` 和 `wait` 毫无关系。

如果你坚持要有意义的名字，那我建议用这些：

```python title="Semaphore operations"
fred.increment_and_wake_a_waiting_process_if_any()
fred.decrement_and_block_if_the_result_is_negative()    
```

我不认为世界很快会接受这两个名字中的任何一个。在此期间，我（多少有些随意地）选择使用 `signal` 和 `wait`。

## 为什么用信号量？

单看信号量的定义，完全看不出它们为何有用。诚然，我们并不*需要*信号量来解决同步问题，但使用它们有一些好处：

-   信号量施加刻意的约束，帮助程序员避免出错。

-   使用信号量的解法往往清晰而有条理，容易论证其正确性。

-   信号量在许多系统上都能高效实现，因此使用信号量的解法可移植，而且通常高效。

[^1]: 如果你会说荷兰语，`V` 和 `P` 并非完全没有意义。
